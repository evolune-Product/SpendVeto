How to stop a runaway AI agent loop before it runs up a bill

Put the agent behind SpendVeto: it fingerprints each agent's last tool call and its result, and when the same successful call returns the same result six times within five minutes (both configurable) it freezes that agent before the next model call is paid for. Budgets, a per-minute rate limit and a manual kill switch catch whatever the loop detector doesn't.

Why a budget alone isn't enough

A budget limits how much a loop can cost. It doesn't notice the loop. An agent repeating the same failing plan burns its whole daily budget, and the work is lost too. Public reports put the bills in four and five figures: about $6,000 overnight from one Claude Code command, and about $50,000 in under an hour in a cited red-team case.

How the loop detector works

  1. For every model request, SpendVeto fingerprints the agent's last tool call and its result, with ids, cache markers and thinking stripped so that only behavior counts.
  2. If the same fingerprint appears 6 times within 300 seconds, the agent is frozen (source llm-loop), and its next request is refused before the provider sees it.
  3. Only successful repeats count. An SDK retrying a failed request is being careful, not looping.
  4. A human reviews and unfreezes the agent in the Console or with spendveto unfreeze.

  "$schema": "https://spendveto.com/schemas/policy-v1.json",
  "llm": { "loop": { "enabled": true, "threshold": 6, "windowSeconds": 300 }, "maxRequestsPerMinute": 60, "dailyBudgetUSD": 25 }
}

The other three stops

  • Rate limit. More than maxRequestsPerMinute gets a real 429 with retry-after, so well-behaved clients slow down instead of hammering.
  • Budgets. Daily, hourly, per-request and per-session caps per agent, checked before each request.
  • Kill switch. spendveto freeze <agent> refuses everything from that agent. For agents that pay with x402, a burst of payment attempts (10 inside 10 seconds by default) freezes the wallet automatically.

Try it without blocking anything

spendveto observe   # record what would have been blocked or frozen; block nothing
spendveto enforce   # turn enforcement back on

Observe mode books every request with a wouldBlock note, so you can tune the threshold on real traffic before it ever stops an agent.

Questions

What is an AI agent kill switch?

A control that stops an agent from spending or acting immediately, regardless of what it is doing. In SpendVeto, freezing an agent refuses every model request and payment it makes until a human unfreezes it — from the Console or with spendveto freeze.

Will the loop detector stop legitimate repeated calls?

Only identical successful tool calls with identical results count, and the threshold (6 in 5 minutes by default) is configurable. Observe mode shows what would have been frozen before you enforce it.

Does it work for agents built with LangChain or CrewAI?

Yes, if they call an OpenAI- or Anthropic-compatible API: point the framework's base URL at SpendVeto. Loop detection works on the requests themselves, whatever framework sends them.
