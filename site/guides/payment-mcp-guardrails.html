How to put guardrails on payment MCP servers

Launch spendveto guard in place of the provider's MCP server. The agent still sees Razorpay's, Stripe's or PayPal's own tools, but every call that isn't a read is decided by SpendVeto first: refunds and transfers are priced and checked against your budget, risky changes wait for a human, unknown tools are refused, and nothing but reads gets through if SpendVeto is down.

Why this matters

Payment providers now publish MCP servers so AI agents can work with them directly: Razorpay launched India's first, and Stripe, PayPal, Cashfree and Square followed. With a merchant key, an agent can refund a payment, transfer to a connected account or accept a dispute in one tool call. The provider checks that the key is valid. Nobody checks whether the agent should be doing it, at that amount, today.

Swap one line in your MCP config

{
  "mcpServers": {
    "razorpay": {
      "command": "npx",
      "args": ["-y", "spendveto", "guard", "razorpay"],
      "env": {
        "RAZORPAY_KEY_ID": "rzp_live_…",
        "RAZORPAY_KEY_SECRET": "…",
        "SPENDVETO_AGENT": "support-agent"
      }
    }
  }
}

Use stripe, paypal, cashfree or square the same way, or generic --url … for any other MCP server. The keys stay in the guard's environment on your machine; SpendVeto only sees the tool name, its arguments and the decision.

What the guard decides

KindExamplesDefault

Money outRefunds, transfers, payoutsPriced in USD at your declared rate, then the per-call cap, daily budget, velocity limit and kill switch; a human above the approval line or for a new recipient
RiskyAccepting a dispute, cancelling a subscription, revoking a saved card, sweeping the balance to the bankA human approves
UnknownA tool the profile doesn't recogniseRefused, never guessed

The details that matter for real money

  • Full refunds. A refund with no amount refunds everything, so the guard reads the payment first and prices that.
  • One-tool APIs. Stripe exposes most actions through a single stripe_api_write tool; the guard classifies each call by the API it hits, so a refund is governed and a product update isn't.
  • Rupees and other currencies. Amounts count against your USD budgets only at an exchange rate you declare. With no rate, the money doesn't move.
  • Fail closed. If SpendVeto isn't running, only reads pass.

Questions

Which payment MCP servers does the guard support?

Razorpay, Stripe, PayPal, Cashfree and Square have built-in profiles, plus a generic profile for any other MCP server. Each profile knows which of the provider's tools read, collect money, move money out, or change something risky.

What happens when the agent asks for a refund above the limit?

The guard refuses the call before the provider sees it and returns a tool error with a code and a fix. Above the approval line it waits for a human instead: they approve in the SpendVeto Console and the agent repeats the same call.

Does SpendVeto hold my Razorpay or Stripe keys?

No. The keys stay in the guard's environment on your machine, the same place the provider's own MCP server would read them. SpendVeto's server only sees the tool name, its arguments and the decision.
