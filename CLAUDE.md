# CLAUDE.md — working on SpendVeto

SpendVeto is the spend-governance layer for AI agents that pay for things — model tokens, x402/USDC, cards, fiat payouts. Rails move the money; SpendVeto decides whether the agent is allowed to move it — before anything settles. Since v0.29.0 it is also the neutral trust layer between agents and sellers: attestations, federated reputation, an open policy schema.

**Proprietary since 2026-10-25.** Copyright Evolune EdgeTech LLP (`LICENSE`); the GitHub repo is private and `package.json` has `"private": true`. Never re-add "open source" / Apache-2.0 claims, GitHub repo links, `git clone` instructions or the `uses: …@main` action to the site, README, docs or pitch material — public docs point at `npx spendveto` and `https://spendveto.com` (the network spec is served from `site/spec/NETWORK.md`; keep it a copy of `docs/NETWORK.md`). Versions before 0.32.0 were Apache-2.0 and stay so for whoever received them. Publishing to npm again is the user's decision: it means removing `"private": true` deliberately.

## The one rule that governs everything

**Every public claim must be an assertion in `npm run verify`.** The count in README/site/PITCH must equal what **a fresh clone** produces — `npm run verify 2>&1 | grep -c "^PASS"` (currently **492**), not what this machine produces. Three further assertions cover the real cross-project Basis integration and only run when `../prediction-copilot` sits alongside this repo, which takes a maintainer checkout to 461. Publish 492: a reviewer who clones and counts must never find the site claiming more than they can reproduce. New feature → new assertion(s) → bump the count everywhere it appears (grep for the old number across `README.md PITCH.md site/*.html launch/*.md`). Never ship a fake control: features that can't work locally yet are *declared slots that refuse honestly* (see `rails/index.js` roadmap rails), never stubs that pretend.

## Hard-won gotchas

- **Chain SDKs are optional peer dependencies — never import one statically.** `@x402/*`, `@solana/kit`, `@aptos-labs/ts-sdk`, `@stellar/stellar-sdk`, `@hiero-ledger/sdk` and `xrpl` load through `loadOptional()` (`server/optional.js`) at the moment a chain settles; a static `import` anywhere on the boot path (server/index.js, client/wallet.js, rails/) breaks the default install, which no longer has them. A new chain family goes in `FAMILY_PACKAGES` there and in package.json as an optional peer AND a devDependency with the same range (verify checks both). Verify proves it on the `npm pack` output with every one absent.
- **mppx is a pinned devDependency behind an npm override** (`overrides.mppx.express: "$express"`): its optional peer wants Express 5, SpendVeto stays on Express 4 and never loads `mppx/express`. Overrides only apply to the root project, so users never see it. Before bumping mppx, re-check its viem minimum (2.57.1 at 0.13.5) and its session wire format — it ships fast (117 releases Feb–Oct 2026), and the Tempo method drafts lag the SDK. `server/mpp.js` stays dependency-free: it parses the `Payment` auth scheme itself, so mppx is only the suite's source of real challenges and the client it governs.
- **Spend is `paid` OR `unmanaged`.** Unmanaged entries (money a governed wallet moved around the gate, found on-chain by `server/outofband.js`) count in the hourly budget and delegation caps (`client/policy.js`). Any new budget filter must include both, or the caps go back to counting only what the agent chose to route through SpendVeto. Analytics, FOCUS export and trust scores still read `paid` only, on purpose — they describe governed spend.
- **MCP guard profiles are code, not config** (`PROFILES` in `server/mcpguard.js`). When a provider renames or adds a tool, add it there with its kind. An unknown write is refused by default, which is the safe failure, but it will surface as `mcp_tool_unclassified` for users. Spend amounts are read from several candidate fields because the providers don't publish schemas; keep `scripts/fixtures/mock-payment-mcp.mjs` in step with any Razorpay tool you add a rule for.
- **Free the ports before `verify`, one port at a time**: `for p in 8384 8385 8386 8388 8391 8401 8402 8404 8493 8496 8497 8498 8499; do lsof -ti :$p | xargs kill -9 2>/dev/null; done` (8384 = the suite's local JSON-RPC node for out-of-band scans, 8385 = the suite's local MPP seller, paid by the real mppx client, 8388 = the suite's no-chain-SDK server booted from the `npm pack` output, 8386 = its mock Anthropic upstream, 8391 = the suite's relocated-data-dir server, 8493 = its seller app behind `requireGovernedAgent`, 8496 = its mock fiat providers + Stripe Billing, 8497 = its mock LLM provider, 8401 = the suite's testnet-mode server, 8498 = its mock facilitator). Multi-port `lsof -ti :8402 :8404` fails silently → a stale server keeps the port → verify's own server dies EADDRINUSE and the suite runs against old code with leftover in-memory state. The boot check now names EADDRINUSE explicitly.
- Verify wipes `data/{ledger,balances,delegations,children,freezes,waitlist}.json` at start and restores `data/policy.json` in `finally` — restart the demo servers and reseed after a run.
- Suite bookkeeping is exact: paid/blocked ledger counts and blocked-USD totals are asserted. Adding a test call means updating the counts in the stats/ledger assertions.
- Payment header is `address:nonce[:chain]:signature`; the chain is inside the signed message (`nonce:resource:price:chain`). Three-part headers settle on `base-sepolia` (legacy/raw-test compat).
- `data/children.json` holds child private keys (simulate demo money only) — gitignored, keep it that way. `.env.local` likewise.
- **Paid routes are gated for `HEAD` as well as `GET`** in testnet mode (`server/index.js` `routes`): Express runs the GET handler for a HEAD request, so a GET-only x402 rule leaves the paid handler reachable unpaid. Any new paid route needs both.
- **EVM 402s carry the token's own EIP-712 domain** from the registry's `eip712` (Circle mainnet USDC = "USD Coin", testnet = "USDC"). New EVM chain → verify its domain with `npm run check-chains`, never assume. XRPL ids: `xrpl:0` mainnet (opt-in via `SERVER_PAYOUT_ADDRESS_XRPL_MAINNET`), `xrpl:1` testnet.
- **Runtime state goes through `dataPath()` / `DATA_DIR` from shared-config.js**, never `new URL("../data/…")`: `SPENDVETO_DATA_DIR` relocates it (the CLI uses `~/.spendveto` for installed copies). Shipped assets (policy packs) use `PACKAGE_DATA_DIR`. verify.mjs still reads/writes `${ROOT}data/…` because its server runs with the default.
- **The LLM guard and card webhooks must stay mounted before `express.json()`** in server/index.js — moving them after it truncates bodies at 100 KB and breaks signature verification.
- **The policy schema is the contract for every policy key.** A key the engine reads but `spec/policy-v1.schema.json` doesn't list is reported as unknown (CLI, API, the boot warning, the GitHub Action). New policy key → add it to the schema AND to verify's `everySection` policy, then `cp spec/policy-v1.schema.json site/schemas/policy-v1.json` (verify asserts the hosted copy is byte-identical). The validator refuses a schema using any keyword it doesn't implement — add the keyword to `server/policyspec.js` first.
- **One instance key signs everything** (`instanceSigner` in server/simulate.js: receipts, verdicts, consents, bindings, attestations, reputation feeds). Every new signed artifact needs its own message prefix (`spendveto-<kind>:…`) so no signature can be replayed as another kind.
- Shell cwd resets between tool calls — always `cd /Users/.../spendveto &&` or use absolute paths (a `rails/` dir once landed in `$HOME`).

## Governance API (`govern/`, :8405)

Reserve-then-settle spend control for API/LLM spend, multi-tenant, **Postgres-backed** — a separate service that shares no storage with `server/`/`proxy/` and changes nothing about them. Full reference: `govern/README.md`.

- `npm run govern` (needs `SPENDVETO_DATABASE_URL`), `npm run govern:admin -- create-tenant --name X` (first admin key; there is deliberately no unauthenticated HTTP way to mint one).
- **Lock order is the correctness argument** (top of `govern/engine.js`): reservation → approval → budget rows sorted by id → per-tenant audit advisory lock, always last. A new code path that appends an audit event and *then* locks a budget row can deadlock against `authorize` — return the event and append it at the end (see `upsertBudgetTx` in `admin.js`).
- Money is integer micro-USD in BIGINT; `db.js` parses int8 to Number and throws if it's not a safe integer. Metadata is flat and float-free because it is part of the idempotency fingerprint and must hash identically after a JSONB round trip.
- `npm run test:govern` — real Postgres via `GOVERN_TEST_DATABASE_URL` (DB name must contain "test"; the suite drops the sv_ tables). Includes a two-process race and the Python SDK e2e. **Not in the published verify count** (same reason as the sanctions tests: needs infrastructure a fresh clone may not have) — don't add these to README/site counts.
